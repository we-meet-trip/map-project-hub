# 0003. 마이그레이션 자격과 서비스 자격을 나눈다

## 맥락
서비스와 마이그레이션이 같은 DB 자격을 쓰면, 서비스 쪽 결함 하나로 스키마를 바꾸거나 다른 서비스의 데이터를 읽을 수 있다. 여러 서비스가 한 PostgreSQL 을 함께 쓴다.

## 선택지
1. 하나의 자격으로 서비스와 마이그레이션을 모두 돌린다.
2. 서비스는 기동 때 스스로 마이그레이션한다.
3. 소유자(로그인 없음)·migrator·runtime 세 역할로 나누고, 마이그레이션은 별도 일회성 작업으로 돌린다.

## 결정
3. `scripts/database-roles.sql` 이 역할과 권한 목록을 만든다. 서비스는 `map_hub_runtime` 으로만 접속하고, 기동 때 역할·권한·리비전 head 를 검사해 맞지 않으면 뜨지 않는다. 마이그레이션은 `python -m map_project_hub.db.migrate` 를 migrator 자격 하나로만 실행한다.

## 결과
- 런타임은 DDL·소유 역할 전환·다른 데이터 읽기를 할 수 없고, 이 "할 수 없음"을 빈 PostGIS 에서 시험으로 고정했다(CI `database-isolation`).
- 새 테이블을 만들면 역할 SQL 의 권한 목록도 고쳐야 런타임이 쓸 수 있다(닫힌 쪽 기본값).
- 빈 DB 의 첫 마이그레이션에는 운영자가 DB CREATE 권한을 잠깐 주고 거두는 단계가 필요하다.
