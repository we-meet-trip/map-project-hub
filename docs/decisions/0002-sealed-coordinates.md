# 0002. 좌표는 봉투로만 주고받는다

## 맥락
사용자의 위치·이동 경로는 좌표 두 개만으로도 드러난다. 좌표가 쿼리 문자열에 실리면 접근 로그·프록시 로그·캐시 키에 평문으로 남는다. 로그 가림 규칙으로 막으려 했지만 이름 변형(`start_lat` 등)을 놓친 적이 있다.

## 선택지
1. 평문 좌표를 받고 로그에서 가린다.
2. 서비스 사이 좌표를 AES-GCM 봉투로 감싸고, 열쇠가 있을 때만 봉투를 요구한다(없으면 평문 허용).
3. 봉투만 받는다. 열쇠는 필수이고 없으면 부팅하지 않는다.

## 결정
3. user·agent·hub 가 같은 32바이트 열쇠(`MAP_PROJECT_LOCATION_WIRE_KEY`)로 좌표를 `loc` 하나에 감싸 보낸다. hub 는 봉투를 연 뒤 국내 범위를 다시 보고, 봉투가 없거나 틀리면 400 으로 거절한다. 평문 좌표를 받는 길은 두지 않는다. 주변 장소처럼 응답에 요청 위치가 드러나면 응답도 감싼다.

## 결과
- 쿼리·로그·캐시 키에 원시 좌표가 남지 않는다. 좌표를 열었다는 사실만 기록한다.
- 혼자 띄워 볼 때도 열쇠를 만들어야 한다(`openssl rand -base64 32`). 시험은 합성 열쇠를 쓴다.
- 2안은 감싸는 쪽이 조용히 고장 나도 평문이 흐르는 상태를 남겨 택하지 않았다.
